Nginx 網頁伺服器

設定檢查、路由、反向代理、容器環境與錯誤排查。

27 條指令與設定·4 個分類·搜尋・複製・收藏

注意：本頁「設定」類的內容必須放入 Nginx（網頁伺服器）設定檔，不是在終端機直接執行的 Shell（命令列）指令。

01

狀態與設定檢查

檢查服務與輸出目前的有效設定。

8 條
顯示 Nginx 版本環境

查看 Nginx（網頁伺服器）版本號。

補充不需要修改服務即可執行。

nginx -v
顯示詳細編譯資訊檢視

列出編譯參數與模組資訊。

補充可確認是否有需要的模組。

nginx -V
測試設定檔語法檢查

檢查 Nginx 設定語法與基本檔案可用性。

補充修改設定後應先執行此指令。

nginx -t
列出並測試全部設定檢查

輸出主設定與 include（引用）載入內容。

補充可能包含機密設定，分享輸出前請檢查。

nginx -T
平滑重新載入設定謹慎

要求 Nginx 管理程序載入新設定。

注意先執行 nginx -t；仍可能影響長連線與既有工作。

nginx -s reload
查看 Nginx 服務狀態服務

查詢 systemd（系統服務管理程式）的服務資訊。

補充不適用只在容器內執行的無 systemd Nginx。

systemctl status nginx
透過 systemd 重新載入謹慎

依服務單元定義重新載入設定。

注意執行前先測試設定並確認服務單元存在。

systemctl reload nginx
追蹤 Nginx 錯誤日誌日誌

持續顯示伺服器的新錯誤資訊。

補充日誌位置依映像檔或系統設定可能不同。

tail -f /var/log/nginx/error.log
02

路由設定範例

location（路由區塊）、try_files（檔案查找）與錯誤頁。

7 條
指定固定路徑對應檔案設定

將 /aws 精準映射至 /aws.html。

補充需置於 server（網站伺服器區塊）並搭配正確 root。

location = /aws { try_files /aws.html =404; }
配置第二個主題路由設定

讓 /vim 回應獨立的 Vim 頁面。

補充你的筆記網站採用這種靜態頁面路由方式。

location = /vim { try_files /vim.html =404; }
只提供存在的路徑設定

先嘗試實際檔案及目錄，不存在時回傳 404。

補充避免所有未知網址都錯誤回到首頁。

location / { try_files $uri $uri/ =404; }
指定自訂錯誤頁設定

讓找不到頁面的請求顯示指定檔案。

補充還需在相應位置處理避免直接公開系統路徑。

error_page 404 /404.html;
限制錯誤頁只能由內部導向設定

避免直接以網址讀取錯誤頁。

補充搭配 error_page 404 /404.html 使用。

location = /404.html { internal; }
指定靜態網站根目錄設定

設定網站檔案所在資料夾。

補充通常放在 server 或 location 層級。

root /usr/share/nginx/html;
設定目錄預設首頁設定

當請求指向目錄時嘗試 index.html。

補充不保證替代精準路由的需求。

index index.html;
03

代理與靜態內容

反向代理、快取與常見 HTTP（網頁傳輸協定）設定。

5 條
設定反向代理目標設定

將請求傳給後端 HTTP 服務。

補充需要搭配 location，並考慮斜線和路徑轉換差異。

proxy_pass http://127.0.0.1:8000;
傳遞原始 Host 標頭設定

讓後端得知用戶端請求的主機名稱。

補充通常搭配反向代理使用。

proxy_set_header Host $host;
傳遞用戶端位址設定

提供後端來源位址資訊。

補充若前方仍有代理，需評估可信代理與位址來源。

proxy_set_header X-Real-IP $remote_addr;
限制請求主體大小設定

設定上傳內容最大值。

補充超過限制時可能回傳 413；10m 是示範。

client_max_body_size 10m;
設定 HTTP 監聽連接埠設定

在指定 server 區塊監聽 80 連接埠。

補充若對外服務含登入或個資，需規劃 HTTPS（加密網頁連線）。

listen 80;
04

容器化網站

搭配 Docker Compose（容器編排）部署與驗證。

7 條
驗證編排設定檢查

先檢查 YAML（設定格式）與變數替換結果。

補充若有機密環境變數請勿直接分享輸出。

docker compose config
啟動網站容器容器

依目前 Docker Compose（容器編排）檔案啟動。

補充改動掛載設定時可能需要重新建立容器。

docker compose up -d
查看網站服務狀態檢查

確認 Nginx 服務容器是否啟動。

補充狀態為 running（執行中）不保證 HTTP 路由正常。

docker compose ps
容器內測試設定檢查

驗證已啟動的 webserver（網頁伺服器）容器內 Nginx 設定。

補充服務名稱 webserver 依目前範例專案，其他專案需替換。

docker compose exec webserver nginx -t
確認首頁回應HTTP

確認首頁 HTTP 狀態碼及回應標頭。

補充localhost 指的是執行指令的當前主機。

curl -I http://localhost/
確認分類頁路由HTTP

檢查 /aws 是否正確回傳 200。

補充若顯示 404，檢查檔案掛載與有效 Nginx 設定。

curl -I http://localhost/aws
確認 404 回應HTTP

檢查不存在的路徑是否真正回傳 404。

補充自訂 404 頁仍須搭配正確的 HTTP 狀態碼。

curl -I http://localhost/not-found
找不到指令

請調整搜尋條件。
